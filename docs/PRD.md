# 对话微调 · 产品需求文档

> 面向 Tavo 的聊天内容定向微调插件。本文档记录原始需求、补全分析、最终决策与验收标准。

---

## 1. 原始需求

1. 插件专用于对 AI chat 的回复内容或玩家的输入内容进行微调，名称为「对话微调」。
2. 触发方式：在 AI chat 消息或玩家输入上提供「微调」入口；原生长按菜单已有「复制、改写、回溯、删除、隐藏、多选、折叠」，不要与官方或第三方按钮冲突。
3. 点击微调后，在下方弹出输入框，引导用户输入如何微调；页面同时有「使用长记忆」「最近的 N 条对话（N 可输入）」两个开关。
4. 点击确定后组装上下文，调用当前聊天配置的 API 生成。上下文默认只包含当前选择的内容，按开关可叠加长记忆与最近 N 条对话。
5. 该功能是做微调，要做到最小化改写，与用户要求无关的部分原样保留，只修改最必要的部分。
6. 开发前先以产品经理角色分析需求，补齐未说出的需求；整体设计美观大方、符合现代软件习惯、易于使用。

## 2. 平台约束（决定了实现形态）

Tavo 的长按气泡菜单（复制 / 改写 / 回溯 / 删除 / 隐藏 / 多选 / 折叠）是**原生 UI，插件没有注入点**。官方文档明确写道：

> 原生控件始终优先，插件动作随后按稳定插件和 manifest 顺序排列。宽度不足时，只有插件动作进入 action bar overflow……**这个 overflow 不是消息 context menu。**

插件可用的入口只有四个：

| 入口 | 用途 | 与原生控件的关系 |
| --- | --- | --- |
| `contributes.inputActions` | 输入框 `+` 菜单 | 追加在原生项之后 |
| `contributes.lastMessageActions` | 最后一条消息的 action bar | 官方规定插件动作排在原生控件之后，天然不挤占原生控件 |
| `contributes.htmlFragments` + `/messages/end` | 每条消息旁的装饰/按钮 | 完全独立的位置 |
| `contributes.htmlFragments` + `/chat/body/end` | 聊天页级面板 | 独立层，不影响原生菜单 |

**结论**：需求 2 中「在原生悬浮框里加一个微调按钮」无法 100% 实现。采用等价的四路触发：

| 触发 | 说明 |
| --- | --- |
| 每条消息下方的行内「微调」按钮 | 默认显示，可在设置页关闭 |
| 最后一条消息 action bar 的「对话微调」 | 原生位置，插件动作排在原生控件之后 |
| 输入框 `+` 菜单的「对话微调」 | 对应「玩家的输入框」 |

面板统一由聊天页级片段承载，**并且挂在宿主页面文档上**（通过
`window.frameElement.ownerDocument` 拿）：否则 fixed 定位会被限制在气泡那个小 iframe 里
（面板既不在屏幕底部，也小到无法操作）。

跨片段通信走宿主页面窗口的自定义事件（兄弟 iframe 之间 postMessage 到不了），
不使用聊天作用域变量轮询——真机记录显示轮询会持续泄漏文件描述符。

## 3. 需求补全分析

原始需求里没有写、但必须定义的部分，以及本项目的处理方式：

| # | 补全项 | 结论 |
| --- | --- | --- |
| 1 | 微调结果落到哪里 | 预览页提供四个落点：应用到消息（默认）/ 作为新消息 / 填回输入框 / 复制 |
| 2 | 是否先预览再落盘 | 先看前后对照与差异高亮再确认；设置里可开「生成后直接应用」 |
| 3 | 差异如何呈现 | 只展示改写后的正文，字符级差异高亮内联标出（新增绿、删除红删除线），并自动滚动到第一处差异 |
| 4 | 撤销怎么做 | **用原生能力**：应用时写入为该消息的一个候选版本，原文保留在候选历史里，用 Tavo 原生的版本切换切回 |
| 5 | 「最小化」由谁保证 | **由提示词引导，不做自动判断**；设置页提供可编辑的默认引导提示词 |
| 6 | 生成失败 / 未配 API | 保留原文，面板内报错可重试，绝不写入半成品；**不设生成超时**，等不及由玩家自行取消 |
| 7 | 生成中切换聊天 | 保持面板可用，写入失败时提示，不会串改别的聊天 |
| 8 | 空内容 / 流式中 / 隐藏消息 | 无内容或隐藏消息不显示入口 |
| 9 | 群聊多角色 | 追加新消息时继承原消息的 `characterId` |
| 10 | 长记忆与 N 的默认值 | 默认都不开（长记忆关、N=0），贴合「上下文默认只有选中内容」 |
| 11 | 玩家的调整要被记住 | 面板开关状态写入全局变量，下次打开保持上一次的选择 |
| 12 | 隐私告知 | 面板底部明示：开启的选项会随原文一起发送给模型 |
| 13 | 手势冲突 | 长按 450ms 判定、位移超 12px 取消、存在选区时不劫持 |
| 14 | 无障碍 | Esc 关闭、焦点回到触发元素、aria 标签齐全、尊重 `prefers-reduced-motion` |
| 15 | 国际化 | en + zh-CN 双语 catalog，切换语言时完整重渲染 |
| 16 | 交付形态 | README + PRD + LICENSE + 构建脚本产出 `.tpg` |

## 4. 已明确排除的功能

按需求方要求，以下能力**不做**，避免自作主张：

- ❌ 不判断生成结果是否「过于偏离」，不做相似度校验，不自动重写。
- ❌ 不做「明确要求大改时豁免」之类的规则判断。
- ❌ 不做选区局部微调——生成对象始终是**整段内容**。
- ❌ 不对模型输出做清洗（不剥离代码块、引号、前缀）。
- ❌ 不自己实现撤销历史，版本切换交给原生候选机制。

插件只负责这一条主链路：

```
点击微调 → 弹出面板（输入微调要求 + 选项）→ 生成整段新内容 → 预览 → 应用
```

## 5. 交互流程

```
┌──────────────┐   长按        ┌──────────────┐
│ 聊天气泡      │ ───────────▶ │ 行内「微调」  │
│ (或输入框)    │              │ 按钮          │
└──────────────┘              └──────┬───────┘
                                      │ 点击
                                      ▼
                            ┌─────────────────────┐
                            │ 微调面板（底部弹出）  │
                            │ ├ 目标：角色消息·128字│
                            │ ├ 微调要求 [输入框]   │
                            │ ├ 使用长记忆  (开关)   │
                            │ ├ 最近对话  [−] 0 [+]  │
                            │ └ [取消]   [生成微调]  │
                            └──────────┬──────────┘
                                       │ 生成（同一份上下文）
                                       ▼
                            ┌─────────────────────┐
                            │ 预览                 │
                            │ ❶ ❷ ❸  ← 可切换历次  │
                                                        │ 微调后（差异高亮）     │
                            │ [重新生成][复制]      │
                            │ [作为新消息][应用到消息]│
                            └─────────────────────┘
```

## 6. 上下文组装

顺序固定，全部拼进一次请求：

```
[引导提示词]        ← 设置页可编辑，默认引导最小化改写
[长记忆]            ← 开关打开且记忆非空时
[最近 N 条对话]      ← 开关数值 > 0 时，取被微调消息之前的 N 条
[原文全文]
[玩家的微调要求]
[输出语言要求]
[输出格式要求]
```

- 生成走 `tavo.generate(prompt, { context: false })`，**使用当前聊天绑定的模型 API**，不额外附带对话上下文（上下文由插件自己组装，保证可控）。
- 「最近 N 条」取的是**被微调消息之前**的 N 条，而不是聊天末尾的 N 条——微调早期消息时，末尾对话是噪声。
- 原文与要求都要求模型**输出完整的改写后全文**，不是 patch、不是片段。

## 7. 默认引导提示词

```text
你是一个文本微调助手。请按照玩家给出的「微调要求」改写下面的原文，并遵守：
1. 只改动与要求直接相关的部分，其余内容逐字保留，包括标点、换行、格式、称呼、专有名词与情绪强度。
2. 不增删信息，不总结，不续写，不评价原文。
3. 保留原文的人称、时态与语气；除非要求里明确说明，否则不要把叙述改成对话。
4. 输出完整的改写后正文，不要输出改动说明、前言、总结或 Markdown 代码块。
```

这段提示词在设置页可直接改写，是「最小化改写」的唯一保障手段。

## 8. 写回语义

| 落点 | 实现 | 可否退回原文 |
| --- | --- | --- |
| 应用到消息 | `tavo.message.variant.create(id, { content }, { select: true })` | 可以，原文进入候选历史，用原生版本切换切回 |
| 作为新消息 | `tavo.message.append(...)`，继承原角色与 `characterId` | 原消息不受影响 |
| 填回输入框 | `tavo.input.set(text)` | 输入框内容可自行编辑 |
| 复制 | 剪贴板 | — |

## 9. 验收标准

- [x] 每条消息下方有行内「微调」按钮，颜色足够醒目；可在设置页关闭。
- [x] 面板由聊天页承载，无论从哪个入口打开都贴在屏幕底部、尺寸可操作。
- [x] 点击微调后下方弹出面板，含微调要求输入框、两个开关。
- [x] 生成完成后微调要求仍可编辑，改动会用于「重新生成」。
- [x] 去掉长按功能与其设置项。
- [x] 开关状态在下次打开时保持上一次的选择。
- [x] 默认上下文只有当前选中内容；开关打开后按开关叠加长记忆与最近 N 条。
- [x] 生成调用当前聊天绑定的 API。
- [x] 生成结果提供前后对照与差异高亮，自动滚动到第一处差异。
- [x] 「重新生成」使用完全相同的上下文，并保留历次结果可回退。
- [x] 应用到消息后成为该消息的一个版本，原文可用原生方式切回。
- [x] 生成失败保留原文并给出错误提示。
- [x] 全部用户可见文案进入中英文 catalog，切换语言完整重渲染。
- [x] 设置页可编辑引导提示词。

## 10. 风险与已知限制

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 原生长按菜单不可扩展 | 需求 2 无法字面实现 | 四路等价触发 + 设置项切换长按行为 |
| DOM 结构随版本变化 | 长按定位消息容器依赖宿主 DOM | 多级向上查找 + 内容匹配，失败时退化为行内按钮 |
| 模型不听话 | 可能返回解释文字或多余格式 | 默认引导提示词已约束；按需求方要求不做清洗，由玩家自行判断是否应用 |
| 候选存储不可用 | 极老版本或特殊场景 `variant.create` 可能失败 | 退化为直接覆盖，并提示「该楼层没有版本记录」 |
| 长记忆隐私 | 长记忆会随请求发送给模型 | 默认关闭 + 面板内明示 + 开关状态可见 |
